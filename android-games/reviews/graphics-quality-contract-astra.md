## Critical integration findings from actual code

1. **Animation ownership is missing.** `frontline-foundry/scripts/main.gd:108` builds the soldier as separate CylinderMesh/BoxMesh children; campaign `make_world()` builds scenery and enemies from primitives, and `sync_world():473` updates position/scale/text only. Replace this renderer with authored scene instances and a render adapter. Do not add procedural bobbing to the existing helper and call the overhaul complete. Existing direct `get_node("Weapon")`, `get_node("Status")` and `get_node("Health")` accesses (`campaign_main.gd:495,496,526`) must move behind an explicit actor interface or they will break as GLB hierarchy changes.

2. **Current attack events cannot reliably identify the shooter.** `campaign_rules.gd:98` supplies owner *role*, source coordinates, enemy ID and damage, but no recruit ID. `incoming` lacks attacking enemy ID; warning/repair also have incomplete identities. Several recruits share a role. Rover splash calls `hit()` repeatedly for a single attack (`:198-204`), so one recoil/audio event per damage event would visibly overfire. Add bounded, transient presentation metadata at the existing rule emission sites: actor ID, attack sequence, event kind, target ID and optional attachment/effect role. Group one attack with multiple target impacts. Do not reverse-infer identity from approximate positions or HP differences. This is an observational addition, not a combat rewrite.

3. **Rules resolve damage before the cosmetic bolt arrives.** Existing damage is applied in `hit/hurt`, while `make_bolt()` renders a generic 0.2-second traversal. Never move damage/cooldowns into AnimationPlayer callbacks or projectile collisions. Use immediate muzzle/recoil and synchronized hit/health feedback, with short tracer trails; keep any lingering trail cosmetic. Preserve telegraph duration/area exactly for warning attacks. A slow visually authoritative projectile followed by a target dying before arrival fails coherence.

4. **IDs need an attempt namespace.** Recruits use fixed IDs `role_index*3+ordinal`, enemies use scheduled IDs and coins reuse enemy IDs (`campaign_rules.gd:14,151,299`). Use `(render_epoch, entity_type, id)` keys, never bare ID across all node classes. Increment a local epoch on retry, mission switch, successful import/load and scene replacement. Deduplicate events by epoch plus simulation-call/attack sequence and ordinal; do not hash position/time alone or reread the cumulative `event_log` every render frame. Process each emitted event batch once, including multiple simulation substeps.

5. **Reset handling is currently incomplete for a richer renderer.** `make_world():41` clears node arrays and bolts but not `hit_flashes`; retry/load can therefore carry transient flashes onto reused IDs. Centralize clearing of animation blends, interpolation history, hit timers, particles, event cursors, audio queues, camera shake and pending callbacks. Initialize both interpolation snapshots to loaded positions. Freeze presentation time while paused, and clear pending input on resize/modal transitions. On successful load, hydrate pose from current state without replaying old attacks/equips/rewards. Failed import must not reset the current renderer. Handle the deferred `queue_free()` boundary so old callbacks never operate on new actors.

6. **Two Frontline entry paths remain live.** `boot.gd` selects legacy `main.gd` for catalog 1 and campaign subclass for catalog 2; campaign inherits UI/input/helpers from main. State explicitly whether benchmark covers campaign only. Retain legacy boot/save routing and validate one legacy load; do not accidentally force old saves into the new campaign or break inherited methods when extracting rendering.

7. **Current render cost and composition need redesign, not more decoration.** `sync_world():546` destroys/recreates every warning marker on every physics tick, even paused; `mat()` allocates materials per primitive; camera uses a whole-board fit (`campaign_main.gd:226`) and UI has large fixed panels. Use shared materials, persistent keyed warnings, bounded pools and a camera composition fitted to the actual usable region. A conservative camera that keeps the gate/station/front readable is preferable to close zoom that repeatedly hides threats. Check the existing `srgb_to_linear()` material path when migrating colors; compare rendered swatches rather than assuming palette values transfer unchanged.

## Architecture and focused verification contract

- Keep deterministic rule state, seeded decisions, simulation step schedule, save schema/meaning and progression authoritative. Any observational event additions must leave the complete resulting state equal under identical seeded input.
- Rules own world-space x/z and timing. Render roots follow those coordinates; child rigs own pose only. Blend snapshots for smooth display without consuming gameplay RNG. Root motion, navigation/physics collision and mesh extents must not change range, costs, paths or damage. Scenic obstacles respect existing movement geometry.

- Add only meaningful scoped checks: unchanged-state replay with old/new renderer; event-once and multi-target single-attack cases; pause/resume; retry/load/mission-switch with reused IDs; one existing saved campaign plus legacy save read; render hydration with no phantom shots; viewport/input transforms and node/effect count stability. ## Gear window-fit first

Actual source confirms `project.godot` uses 600×1066 + `stretch/aspect="keep"`. `main.gd` draws fixed 600×1066 geometry and assumes the same coordinates for buttons, board cells and input. `campaign_view.gd` changes board origin between ready/battle, but still uses fixed sizes; `campaign_ui.gd` and built-in transfer/menu dialogs also need coverage. Changing only `keep` to `expand` would expose unused space while retaining anchored content; nonuniform stretch distorts circular gears and actors. The source explains a plausible fit mechanism, **not which APK Daniel installed**.

Require a viewport-derived layout shared by drawing and hit testing, with a defined safe content rectangle and aspect-preserving game shapes. Expand/recompose the world and panels to use wide or tall space; preserve board sockets, army field, wall/gates, tray and controls. Keep a stable simulation-to-world mapping independent of screen pixels; transform input once through the inverse layout mapping. Safe insets reserve controls, not giant unused strips. On resize, cancel or correctly reproject active drags without buying/moving a piece; preserve the battle and every save field. Gear's current global clock advances during pause and actor art bobs from that clock (`main.gd:126`, `actor_art.gd:67`); replace this with explicit presentation timing when rigged actors arrive.

For the first fit checkpoint, capture the same ready and active states at baseline 600×1066, cover 1080×2520 and inner 1968×2184, plus an intermediate live resize. These are repository target profiles, not confirmed physical identity. Require no letterbox gutters caused by the old fixed canvas, no cropping/stretching, reachable menus/transfer, correct edge/corner socket drag/drop and unchanged ongoing encounter. Empty scenic margins painted around the old tiny board do not satisfy window fill. Keep physical-device work deferred as Daniel requested.
