## Remaining production gates

1. **Required pooling is not implemented in 01f650a.** `android-games/GRAPHICS-OVERHAUL.md:93` explicitly requires pooling dense actors/effects. Historical `foundry.gd` constructs new actors for new IDs, frees expired corpses, constructs transient mesh nodes and frees them at expiry. Stable active-ID nodes, cached models/materials, MultiMesh scenery and a 48-effect cap do not constitute reusable object pools. Implement bounded role-keyed inactive actors and reusable tracer/impact nodes; reset all prior identity/pose/HP/aim/death/transient state when acquired. Verify actual reuse, caps, pause/Retry/load/resize and same-call contact, then one bounded dense motion passage plus separate unpaced timing. Do not replay the full campaign or all six unchanged long passages.

2. **Captain, siege and carapace remain visually unverified.** The final evidence index explicitly records that these roles are CPU rig/event tested but absent from all six films. Nine roles are observed: beetle, guard, matriarch, mortar, ranger, shell, skitter, spitter and swarm. Full production scope covers all enemy roles/bosses; it cannot be inferred from another role's animation or asset existence. Include the missing roles' actual playable appearance, attack/contact and removal in bounded earned-encounter follow-up evidence (or supply equivalent retained original rendered evidence if it already exists). This is narrow missing coverage, not a whole-campaign repeat.

The coordinator has already assigned the pooling work. Actor/foundry files became dirty after playback while that work began; those edits are **not** included in this review's scores or approval. Preserve 01f650a and these films as historical evidence, then close the exact delta additively. A final pool candidate also needs its own signed/native candidate checks; this report does not approve an Android APK.
