# Android cached-shader diagnostic

This is an internal engine probe for the open `Failed to load cached shader, recompiling.` gate. It is not a game release or a renderer workaround. The shipped game source, official templates, settings and cached files stay unchanged during preparation.

Apply `godot-shader-cache.patch` only to Godot commit `ed1daf0bf001b61586d9930840f2f1394092c079` (4.7.2 stable). Its original `drivers/gles3/shader_gles3.cpp` has SHA256 `17c01277dc3468a1d53081f01a6f7665f5d0f82e7882a8198e1f486ee344d5d8`. Source: https://github.com/godotengine/godot/blob/ed1daf0bf001b61586d9930840f2f1394092c079/drivers/gles3/shader_gles3.cpp. Upstream Godot code is MIT licensed; this patch retains the existing warning and return/fallback branches.

The patch is enabled only by `cppdefines=GAMES_SHADER_CACHE_DIAGNOSTIC`. It logs every reached nonempty cached `glProgramBinary` attempt, including successful loads; file-open/header/version/short-read failures return before that point. These records include shader name, full cache key/path, variant/specialization, transform-feedback names, binary format/offset/length/SHA256, link status, bounded driver info log, supported binary formats and GL implementation strings. Error queries are bounded and occur before program creation, before/after binary load, after link-status inspection and after diagnostic queries. `glGetError` consumes error flags; this observational difference is limited to the diagnostic engine and must not be described as a byte-identical production execution.

A separate size-query record covers even zero-length exports skipped by the original engine. Cache export logs also record the size requested from `GL_PROGRAM_BINARY_LENGTH`, the actual length returned by `glGetProgramBinary`, hashes of the stored buffer and actual written portion, and adjacent error flags. Providing a returned-length pointer and reading GL error flags are explicit diagnostic perturbations. The original buffer, format, cache framing and file write decisions are preserved. No cache is deleted, disabled or rewritten by the probe itself; ordinary engine cache compilation/export remains active. The one-time warning is preserved. Each JSON observation is serialized as UTF-8 and split into 1,536-byte base64 chunks with an atomic per-process record ID, chunk index/count, total byte length and SHA256. Every Android log message contains only bounded ASCII fields (under 3,072 bytes), including when path/feedback/driver strings are long. Driver info itself is capped at 65,536 bytes with truncation reported.

`decode_shader_cache.py <threadtime-log> <new-output.json> --pid <actual-pid>` accepts only complete matching frames, exact byte lengths/SHA256, canonical base64, valid UTF-8/JSON, the expected PID and contiguous observed record IDs starting at zero. It rejects duplicates, gaps, truncated frames and empty collections. The raw log is hash-bound in the output. This proves integrity of observed records; an entire trailing record or absent terminal capture can still be missing, so native collection/lifecycle bounds and command receipts remain necessary. Synthetic transport tests do not establish native shader behavior.

Build dependencies are pinned by upstream: Android NDK `29.0.14206865`, SCons `4.10.1`, Swappy `from-source-2025-01-31`. Keep the one source checkout, NDK and build outputs on F:. Do not replace the official installed template. Build only x86_64 for the existing emulator using `platform=android target=template_release arch=x86_64 production=no debug_symbols=no lto=none swappy=yes cppdefines=GAMES_SHADER_CACHE_DIAGNOSTIC extra_suffix=games_shader_diag -j4`.

Before any native run, independently review the patch and inspect the compiled library. Preserve the exact installed Tower APK, every original save/archive file and full owning context. A diagnostic APK may replace only the x86_64 engine library in a separate local copy of that exact APK, retain package/version/signing continuity, and install over the owned emulator without reset. Record the exact ZIP delta, source/ABI/metadata/signature, install command and unchanged raw save files. Run one no-input launch with actual cache paths/binaries pinned before and after; record native logs, pixels and whole save context. Do not claim a result if no matching cache-key rejection is observed.

Restore the exact original APK by normal same-version install, read back its installed bytes and confirm the full original save through cold launch, then stop the owned emulator. Keep the diagnostic APK local. This probe does not establish phone performance, sound, fun, cloud recovery or a production fix. A cause claim needs a rejected load tied to an exact binary plus driver evidence and a discriminating follow-up; a warning-free unrelated cache namespace is insufficient.

The pinned Android SConscript moves the linked library to `platform/android/java/lib/libs/release/x86_64/libgodot_android.so`. The first successful compile retained a failed runner receipt because the original runner looked only in `bin/`; its separate compiled-output qualification records the real output without rebuilding or rewriting that failure. The runner now inspects the upstream destination. Preserve the APK's original `libc++_shared.so`: the new NDK runtime has different bytes and is outside the engine-only probe.
